# Сертификатная авторизация импортирует материалы в запись подключения

Для самостоятельной сертификатной авторизации подключения (mTLS) пользователь задаёт пути к CA-цепочке, клиентскому сертификату и соответствующему приватному ключу. Подключение импортирует их содержимое в свою штатную запись `auth.json`, а не зависит от исходных файлов во время работы: удаление или замена оригиналов не меняет сохранённую авторизацию. Выбираем независимость сохранённого подключения от исходных файлов вместо автоматического подхвата их изменений; обновление материалов требует явного повторного импорта.

Импортированный приватный ключ защищён файловыми правами штатного хранилища, но не шифрованием или системным хранилищем секретов. Это сознательное сохранение существующей границы хранения секретов проекта; интерфейс должен явно сообщать о создании такой копии ключа.

Поддерживаем клиентский сертификат и CA-цепочку в PEM, а также отдельный PEM-ключ с паролем или без него. Пароль запрашивается скрыто только при импорте; ключ сохраняется в расшифрованном виде, пароль не сохраняется. Это позволяет восстанавливать подключение после перезапуска без повторного ввода пароля и не создаёт ложной гарантии шифрования ключа в `auth.json`.

Этот способ не использует токен доступа, авторизационный ключ или HTTP-заголовок `Authorization`. Импортированная CA-цепочка обязательна и является единственным набором доверенных CA для этого подключения; стандартные CA процесса не подмешиваются, другие подключения не затрагиваются. Проверка сертификата сервера по этой цепочке и имени хоста обязательна; небезопасного режима, аналогичного `curl -k`, нет.

Повторный импорт заменяет CA-цепочку, сертификат и ключ единым набором: сначала читаем и проверяем новые материалы, получаем каталог и проверяем генерацию, затем атомарно заменяем запись подключения. При ошибке прежняя запись сохраняется; обычное редактирование без повторного импорта не требует исходных файлов. Существующий поиск и проверка моделей обязательны также для mTLS; ручной ввод Model ID без каталога в эту задачу не входит.
