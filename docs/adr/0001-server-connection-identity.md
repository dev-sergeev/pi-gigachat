# Подключение сервера владеет авторизацией и выбранными моделями

Одно подключение сервера соответствует одному автоматически созданному провайдеру Pi со стабильным внутренним ID. Имя, адрес сервера и выбранный набор моделей могут изменяться без смены этого ID. В Pi авторизация привязана к провайдеру, а сохранённая сессия идентифицирует модель парой provider ID и Model ID; поэтому человеческое имя нельзя использовать как идентичность подключения.

Вместо независимой копии секрета для каждой выбранной модели сохраняем общую авторизацию подключения. Одинаковые Model ID у разных подключений остаются независимыми вариантами; повтор одного ID внутри подключения удаляется. Старый провайдер `gigachat` продолжает существовать отдельно.

Настройки подключения и его ревизия сохраняются вместе с секретом в одной записи штатного `auth.json`. Запись и обновление OAuth-токенов выполняет публичный `ModelRuntime` Pi с блокировкой его хранилища; чтение списка подключений использует ту же файловую блокировку. Ревизия меняется только при пользовательском редактировании, не при обновлении временного токена. Открытый Pi со старой ревизией должен остановить запрос до обновления подключения, а не отправить новый секрет на старый адрес.

Штатный `/model` всегда показывает внутренний ID провайдера. Человеческое имя подключения включается в отображаемое имя модели для деталей и поиска; пользователь не настраивает провайдеры вручную. Проверки генерации выполняются только по явному действию, а перезапуск восстанавливает сохранённый набор без повторных проверочных генераций.

Основание: исходники [Pi 0.85.1](https://registry.npmjs.org/@earendil-works/pi-coding-agent/-/pi-coding-agent-0.85.1.tgz), сверенные с integrity в `package-lock.json`: `dist/core/model-runtime.js`, `dist/core/auth-storage.js`, `dist/core/session-manager.js`, `dist/modes/interactive/components/model-selector.js`. Публичный контекст команды не предоставляет запись credentials; публичный `ModelRuntime` предоставляет login/logout. Нативные `ui.input` и `LoginDialog` не обеспечивают маскировку секрета, поэтому новый мастер использует собственный маскирующий ввод и собственное состояние множественного выбора.
