# Подключение сервера владеет авторизацией и выбранными моделями

Одно подключение сервера соответствует одному автоматически созданному провайдеру Pi. Для нового подключения название определяет регистрозависимый ID: `LDBR` становится `gigachat-LDBR`. Новые названия и названия при переименовании должны соответствовать `/^[A-Za-z0-9_-]+$/`: только латинские буквы ASCII, цифры, дефис и подчёркивание. Занятый ID, в том числе ID чужого провайдера или записи авторизации не GigaChat, вызывает ошибку; автоматические суффиксы не добавляются.

Изменение адреса, авторизации или выбранных моделей при неизменном названии сохраняет ID. Прежние подключения, включая ID вида `gigachat-server-…` и названия, не соответствующие новому правилу, сохраняются без переименования. Изменение названия создаёт заменяющий провайдер: сначала успешно сохраняется новое подключение, затем удаляется прежнее. Если сохранить новое подключение не удалось, прежнее остаётся.

В Pi авторизация привязана к провайдеру, а сохранённая сессия идентифицирует модель парой provider ID и Model ID. При переименовании ссылки в сохранённых сессиях и настройках модели по умолчанию не мигрируются; пользователь заново выбирает модель через `/model`. Это осознанный выбор пользователя в пользу читаемого ID в штатном селекторе, у которого нет отдельного значка с названием подключения.

Вместо независимой копии секрета для каждой выбранной модели сохраняем общую авторизацию подключения. Одинаковые Model ID у разных подключений остаются независимыми вариантами; повтор одного ID внутри подключения удаляется. Расширение регистрирует только выбранные модели сохранённых подключений: встроенного набора моделей нет, установка и загрузка не меняют модель Pi по умолчанию. Программный провайдер `gigachat` предоставляет транспорт и авторизацию без собственного набора моделей.

Настройки подключения и его ревизия сохраняются вместе с секретом в одной записи штатного `auth.json`. Авторизацию выполняет публичный `ModelRuntime.login` Pi с `InMemoryCredentialStore`; после её успешного завершения `ConnectionStore` сохраняет данные под файловой блокировкой `auth.json`, записывая временный файл с правами `0600` и атомарно заменяя файл хранилища. При переименовании добавление новой записи и удаление прежней входят в одну фиксацию: промежуточного состояния с обеими записями на диске нет. Чтение списка подключений использует ту же файловую блокировку. Обновление OAuth-токенов остаётся в штатном `ModelRuntime`. Ревизия меняется только при пользовательском редактировании, не при обновлении временного токена. Открытый Pi со старой ревизией должен остановить запрос до обновления подключения, а не отправить новый секрет на старый адрес.

Штатный `/model` не изменяется и показывает `model-id [provider-id]`, поэтому новое название естественно видно в ID провайдера. Человеческое имя подключения также включается в отображаемое имя модели для деталей и поиска; пользователь не настраивает провайдеры вручную. Проверки генерации выполняются только по явному действию, а перезапуск восстанавливает сохранённый набор без повторных проверочных генераций.

Основание: исходники [Pi 0.85.1](https://registry.npmjs.org/@earendil-works/pi-coding-agent/-/pi-coding-agent-0.85.1.tgz), сверенные с integrity в `package-lock.json`: `dist/core/model-runtime.js`, `dist/core/auth-storage.js`, `dist/core/session-manager.js`, `dist/modes/interactive/components/model-selector.js`. Публичный контекст команды не предоставляет запись credentials; публичный `ModelRuntime` предоставляет login/logout. Нативные `ui.input` и `LoginDialog` не обеспечивают маскировку секрета, поэтому новый мастер использует собственный маскирующий ввод и собственное состояние множественного выбора.
