# Протокол API принадлежит подключению сервера

Объединение выполняется в текущем пакете `@dev-sergeev/pi-gigachat` с одной командой управления `/gigachat`. При переходе отдельное расширение pi-gigachat-openai отключается: оно использует то же пространство сохранённых provider ID и не должно одновременно владеть теми же подключениями.

Сохранённая история сессий при смене протокола не переписывается; меняется только её исходящее представление для выбранного протокола.

Каждое подключение сервера имеет один независимо выбранный протокол API — GigaChat V1, GigaChat V2 или OpenAI-compatible — для всех своих выбранных моделей. Разные подключения в одном Pi могут одновременно использовать разные протоколы; у нового подключения по умолчанию выбран GigaChat V1.

Прежние записи без указанного протокола также считаются GigaChat V1, без обязательного вопроса при первом использовании. Форматы хранения двух прежних пакетов пересекаются и не позволяют надёжно установить происхождение записи: пользователь сознательно выбрал отсутствие дополнительного шага для прежних V1-подключений вместо автоматической защиты прежних OpenAI-подключений от неверного формата запросов. Прежнее OpenAI-подключение потребуется вручную переключить на OpenAI-compatible; до переключения оно использует V1.

Смена протокола — обновление того же подключения, а не его замена: название и provider ID сохраняются, ссылки из сессий и настроек остаются привязаны к нему. Доступность моделей проверяется новым протоколом до сохранения изменений; при неуспешной проверке прежнее подключение не заменяется.

Способ авторизации выбирается независимо от протокола: токен доступа, авторизационный ключ и mTLS доступны для V1, V2 и OpenAI-compatible. Это включает добавление mTLS в OpenAI-адаптер; допустимость сочетания для конкретного сервера определяется проверкой подключения, а не обещанием универсальной поддержки со стороны серверов.

Основной endpoint генерации и полный адрес каталога моделей настраиваются независимо, с готовыми значениями по умолчанию для выбранного протокола. Это сохраняет возможность нестандартного каталога из соседнего OpenAI-пакета и позволяет сочетать документированные `/v2/chat/completions` и `/v1/models` в V2 без обязательного ручного заполнения обоих адресов.

Явно заданный адрес каталога может иметь другой origin. Каталог и генерация используют одну авторизацию подключения, без отдельного набора секретов для каталога; мастер предупреждает об отправке того же токена доступа или предъявлении того же клиентского сертификата другому серверу. Такая возможность сохраняет поведение соседнего пакета, но требует осознанного доверия обоим адресам.

V2 поддерживает нативные множественные вызовы инструментов Pi в одном ответе модели, включая повторные вызовы одного инструмента с разными аргументами. Сохраняются группировка и идентификаторы вызовов; это не означает обязательного параллельного исполнения самих инструментов. Ограничение V1 одним вызовом на сообщение в V2 не переносится. Реальные запросы к публичному `GigaChat-3-Ultra` подтвердили корреляцию через `function_result.id`, совпадающий с `function_call.id`, включая повторное имя инструмента.

V2 поддерживает обычный JSON и потоковый SSE, включая корректное завершение потока и сборку множественных вызовов инструментов. Как и в существующих адаптерах, по умолчанию используется JSON. Реальный SSE подтвердил фрагменты `messages[].content[]` в `response.message.delta`; `response.message.done` может содержать полный набор вызовов без предшествующих delta, поэтому его содержимое также обрабатывается.

Reasoning V2 поддерживается с явным включением в параметрах конкретной модели и по умолчанию выключен. Рассуждения сохраняются отдельно от текста ответа; формат и доступные уровни должны соответствовать подтверждённому контракту сервера. Для документированного B2Bank V2 поддерживается `medium`; существующие V1/OpenAI уровни не переносятся безусловно на публичный V2.

Мастер `/gigachat` выполняет шаги в следующем порядке: способ авторизации → название и данные авторизации → протокол API → адрес генерации и каталог моделей → авторизация, каталог и проверка моделей → выбор моделей → сохранение. Адреса вводятся после выбора протокола, чтобы предлагать соответствующие значения по умолчанию; для нового подключения предвыбран V1, для редактируемого — его сохранённый протокол.

При смене протокола автоматически пересчитываются только стандартные значения по умолчанию. Произвольный основной endpoint и явно заданный полный URL каталога сохраняются; пользователь видит их на шаге адресов и при необходимости исправляет перед проверкой подключения.

Выбор трёх протоколов относится только к сохранённым подключениям Pi, управляемым через `/gigachat`. Нынешние библиотечные экспорты текущего пакета, включая `gigachatProvider` и `streamSimpleGigaChat`, сохраняют V1-контракт; новый программный переключатель протоколов и перенос OpenAI-библиотечного API соседнего пакета в эту задачу не входят.

Граница V2 — существующее назначение интеграции Pi: текст, пользовательские инструменты Pi, JSON/SSE и рассуждения по согласованным правилам. Новая загрузка файлов, мультимодальность и управление встроенными инструментами GigaChat, включая генерацию изображений и 3D, в объединение не входят.

Решение реализовано в общем пакете; миграция на официальный SDK остаётся отдельной задачей. Первичные источники, фактические ответы публичного `GigaChat-3-Ultra` и границы проверки приведены в [исследовании V2](../research/gigachat-v2-api.md).
